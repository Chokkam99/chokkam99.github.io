Built

  • I built the company's self-service developer platform end to end. One workflow sets up everything a new service needs to ship: its code repository, container registry, Kubernetes namespace and deployment pipeline, with no routine manual work from the platform team.

  • Every new service needs the same groundwork: somewhere for its code, somewhere for its container images, a place to run, and a pipeline to deploy it. If each piece is a separate request to the platform team, every new service starts with a wait, and every team sets it up a little differently. With many teams shipping services, that groundwork has to be self-service and come out right by default.

  • When a team arrives with a new design, I often represent the platform. I lead the session, map their stack to the patterns the platform supports, work out what it needs for infrastructure, security, networking, observability, identity and deployment, split the work between teams, write the platform stories, and follow through until it runs in production on a supported setup.
